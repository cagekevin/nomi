# 配置化（config-ize）候选清单

> 探索范围：`docs/` 全量核心文档 + 现有代码中的 config 先例。
> 目的：回答「哪些目前硬编码在代码/文档里、但本质是配置」——给后续 AI 一份**去重后的**候选清单，不是罗列，而是区分「**已在 config**」与「**真正待 config**」，避免重复造轮子。
> 日期：2026-08-10

## 一、先说结论（判断框架）

「适合写成 config」不是「凡是能变的就是 config」。判断一条是否值得 config 化，用两条硬标准：

1. **变化频率**：是否会被频繁改（厂商调接口、产品调阈值、换环境）。一辈子不动一次的常量，抽成 config 是增实体（违反奥卡姆剃刀）。
2. **是否已 config**：项目已有成熟的 config 先例（`model-catalog.json`、`src/config/knownVendors.ts`、`src/theme/nomiTheme.ts`、`electron/runtimePaths.ts`、`electron/capabilityCore/mcpConfig.ts`）。**先查现状再动手，别把已 config 的再抽一遍。**

> ⚠️ 重要提醒：本次探索发现，docs 里很多「看似硬编码」的值，**代码里其实已经 config 化了**（见下方「已在 config」标注）。真正待 config 的，是少数「文档自证是问题」的漏网点 + 分散在多处、缺单一真相源的项。

## 三、真正待 config（本次探索的净产出）

以下按优先级分组，**每条都给出「为什么值得做」+「收敛点」**，不做就保持现状也不致命（多数是低危漂移）。

### P0 · 高杠杆，建议先做

**1. 硬编码阈值 / 限制（`limits`）** — 分散在多个文件，无单一真相源，改一处漏一处。
| 配置项 | 当前值 | 散落位置 |
|---|---|---|
| 图片导入上限 | 30MB | 素材导入链路 |
| 视频导入上限 | 600MB | 素材导入链路 |
| 单次拖入上限 | 8 个 | 素材导入链路 |
| 图片 data-url 降级阈值 | ≤512KB | 素材导入链路 |
| 上传上限（hardenedFetch） | 200MB | 资产本地化 |
| 资源池 limit | 500 | `useWorkspaceFiles` / reference-v4 |
| 参考图上限 | image≤9/video≤3/audio≤3 | 多处 |
| 节点 defaultSize | text 280×200 等 16 种 | 节点契约表 |
| 节点落点间距增量 | 64 | 节点契约表 |

> 收敛点：建议抽一个 `src/config/limits.ts`（纯字面量 + 类型），不引业务。

**2. 超时 / 重试（`timeouts`）** — 多环境差异最大，Lovart 网关这类的坑都在这。
| 配置项 | 当前值 |
|---|---|
| 轮询超时（视频/图） | 300s / 240s |
| 轮询间隔（视频/图） | 3s / 1.5s |
| 聊天双超时闸 | 首字 30s / 整体 120s |
| 渲染层加载重试 | 20 次 / 500ms |
| IPC 慢调用阈值 | >500ms |

> 收敛点：并入 limits 或单独 `src/config/timeouts.ts`。

### P1 · 中价值，与「已在 config」相邻

**3. 供应商生命周期 / 能力声明（`vendor-lifecycle`）** — 文档明言会变。
- Imagen 2026-06-24 停、Sora 2026-09-24 停 → 模型下架时间建议进 catalog 的 lifecycle 字段（与模型清单同源）。
- 参考图 max（各家 14/16）→ 应随模型档案声明，`character-fixation §5.5` 已明言「不是写死常量」。

**4. 脱敏 / 安全字段清单（`secrets-redact`）** — ✅ **已落地，划掉**：`electron/events/redact.ts` 已是单一真相源（`SECRET_KEY_NAMES`/`SECRET_VALUE_PATTERN`/`SECRET_QUERY_PARAM_PATTERN` + 共享 `redactDeep`），日志与安全门岗共用，无需新建（见 §5.2）。

**5. 质量门阈值（`quality-gates`）** — 跨文档重复，改基线要同步多处。
- 单文件 800 行硬上限、软目标 400–500 行
- lint `max-warnings=98` 棘轮、console 迁移基线 ~95 处
- 审计周期 ≥25 commit

### P2 · 低危漂移，文档已自证，可选做

**6. 设计 token 漏网 hex** — 真相源 `tailwind.config.ts` 里确实混 hex（非文档原说的 nomiTheme.ts）。
- `--nomi-axis-x:#ef4444` / `-y:#16a34a` / `-z:#3b82f6`：用户拍板"主题无关、明暗同色"，可保留 hex。
- `--tc-color-app-bg-strong:#020409`、`#f7f9ff`、`#e4ebfb`、`#111321`、`--handle-color-image:#7dd3fc` 等：第三方/未对齐项，应回收进 oklch token（`check:tokens` 门岗只拦新增不拦存量，存量需手动回收）。
- `design/nomi-design-system.md` 自证的 `#2e2c2a`（app 图标）在 .ts 里 grep 未命中，可能已改或在别处。

**7. toolchain 版本约束** — Node ≥20.19.0 / pnpm 10.8.1 / onlyBuiltDependencies 白名单。适合进 `package.json` engines + 现有门岗脚本，不一定要新 config 文件。

### 明确建议「不 config 化」（克制）

- **导出默认规格** MP4 1080p/30fps：产品默认值，用户端可覆盖，抽 config 收益低。
- **提示词模板**（character-fixation 大段中文）：除非要做「多语言模板」，否则抽 config 徒增实体。
- **代理地址** `127.0.0.1:7897`：用户环境项，本就该在用户侧配置，不是产品 config。

## 四、落地建议（如何收敛，符合工程纪律）

1. **不新建大而全的 config 文件**。按 AGENTS.md「如无必要勿增实体」，先做 P0 的两个（`limits` / `timeouts`），其余按需并入现有真相源。
2. **复用现有机制优先**：
   - 供应商相关 → 进 `model-catalog.json` / `knownVendors.ts`（已有类型）
   - 设计漏网色 → 回收进 `tailwind.config.ts` 的 `:root` 真源（已有 token 体系，`nomi-tokens.css` 仅兜底）
   - 安全清单 → 抽共享 `redact.ts` 供日志 + 门岗复用
3. **每做一处，同 commit 删旧硬编码**（P1「加新必删旧」），不留并行版。
4. **单一真相源是目的，config 文件是手段**。若某值只在代码一处出现且不会变，就让它留在原地——config 化不是 KPI。
