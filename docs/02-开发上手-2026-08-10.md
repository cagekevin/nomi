# Nomi 开发上手指南

> 面向要动手改 Nomi 源码的开发者。读完这份 + `AGENTS.md`（项目纪律总纲）+ `docs/engineering-rules.md`（规则详解），你就能安全地下手。
> 配套文档：01-用户指南（安装启动）、`docs/architecture/*`（各子系统架构）、`docs/guide/*`（能力核/MCP 等）。

---

## 0. 一句话定位

Nomi 是一个 **本地优先（local-first）的 AI 视频创作工作台**：Electron 桌面壳 + React 渲染层。用户走「项目库 → 创作（文本）→ 生成画布（节点系统）→ 时间轴预览 → 导出 MP4」这条价值链。

技术栈：**Electron + React 18 + Tailwind 3 + Zustand + Vercel AI SDK + TypeScript**。

---

## 1. 启动开发（快速回顾）

```bash
# 环境要求
node -v          # ≥ 20.19.0（本机 24 已验证）
corepack -v      # 启用 pnpm 版本锁定
corepack enable
corepack prepare pnpm@10.8.1 --activate

# 安装（会下载 Electron + ffmpeg/ffprobe 等体积较大的二进制，耐心等）
pnpm install

# 启动：Vite 渲染服务 + Electron 主进程，自动打开窗口
pnpm dev
```

`pnpm dev` 的实际流程（`scripts/dev-electron.mjs`，读懂它你就懂 dev 全貌）：
1. 找一个 5273 起的空闲端口起 **Vite 渲染服务**（dev server）
2. `tsc -p electron/tsconfig.json` 把主进程（TypeScript）编到 `electron/*.js`
3. `build-tailwind.mjs` 生成 `tailwind.generated.css`
4. 注入 `NOMI_DESKTOP_DEV=1` 等环境变量拉起 Electron，加载渲染服务 URL
5. 窗口默认按 `electronRendererUrl` 落到 `#/studio`

> Windows 控制台中文乱码防护、onboarding agent 自动读 `.secrets/agent.key` 等都在这脚本里处理好了，正常 `pnpm dev` 无需关心。

**调试渲染层**：开发模式下窗口自动 `openDevTools`（detached）。或者直接按 `F12` / `Ctrl+Shift+I` 看组件树、console、网络。

## 3. 代码架构：前端 / 桥 / 后端 三层职责

理解 Nomi 最关键的一点：**它不是一个普通 React 应用，而是「渲染进程（前端）/ IPC 桥 / 主进程（后端）」三层分离**。每一层职责边界清晰，跨层只能通过桥，不能越级直连。

```
┌──────────────────────────────────────────────────────────────────────┐
│ ① 前端 / 渲染进程 (src/)              React 18, Chrome 运行时          │
│   职责：画 UI、持临时交互状态（Zustand）、发指令、收结果重绘             │
│   入口    main.tsx / NomiRouterApp.tsx（HashRouter）                    │
│   工作区  workbench/  画布(generationCanvasV2) / 时间轴 / 创作 / 预览   │
│   设计    design/     token-only 组件（唯一可视化原子入口）            │
│   配置    config/     模型选项 / 档案解析                               │
│   ⛔ 禁止：直接碰 Node / 文件系统 / ffmpeg / 模型供应商                 │
└───────────────────────────────┬──────────────────────────────────────┘
                                 │ 只调 window.nomiDesktop（TS 封装）
                                 ▼
┌──────────────────────────────────────────────────────────────────────┐
│ ② 桥 (Bridge)  唯一跨进程出口，前后端都不能绕过它                       │
│   electron/preload.ts      contextBridge.exposeInMainWorld("nomiDesktop")│
│                             ← 把后端能力暴露成 window.nomiDesktop        │
│   src/desktop/bridge.ts    window.nomiDesktop 的 TS 类型封装             │
│                             ← 业务代码 import { nomiDesktop } 的唯一入口 │
│   ⚠️ 现状坑：channel 名是裸字符串，散在 main/preload/bridge/前端四层，   │
│      改名/改参数要手工翻四处，编译器不查（解耦方案见下方 3.5）          │
└───────────────────────────────┬──────────────────────────────────────┘
                                 │ IPC (ipcMain.handle / ipcRenderer.invoke)
                                 ▼
┌──────────────────────────────────────────────────────────────────────┐
│ ③ 后端 / 主进程 (electron/)          TypeScript, Node 运行时            │
│   职责：落盘持久真相、跑模型供应商、ffmpeg 导出、窗口/生命周期/IPC 注册  │
│   入口    main.ts          窗口/生命周期/IPC 注册（核心入口）           │
│   编排    runtime.ts       ⚠️ 符号百货层：从 20+ 子模块 re-export，     │
│                            catalog/ 反向依赖它 → 改 TaskResult 要翻 36  │
│                            文件（解耦方案见下方 3.5）                    │
│   目录    catalog/         模型目录 vendor/model/mapping（131 文件，     │
│                            = 声明驱动多供应商的诚实代价，合并违反 P1）   │
│   域服务  export/ ffmpeg 导出 · providerAdapter/ 供应商适配 ·           │
│            capabilityCore/ 能力核(MCP) · ai/ agent · tasks/ 任务 ·      │
│            projects/repository.ts 项目持久真相 · assets/ 资产本地化 ·   │
│            workspace/ memory/ conversations/ …（各业务域）              │
└──────────────────────────────────────────────────────────────────────┘
```

**三层职责一句话**：
- **前端**只管「看见什么、点了什么」，不碰 Node；
- **桥**是「唯一电话线」，前后端都只能通过它说话，且目前靠裸字符串对接（脆弱点）；
- **后端**是「真相与重活」——所有持久数据、模型调用、导出都在这里，但被 `runtime.ts` 百货层糊了一层，导致改一处要动多处。

### 3.1 主进程入口 `electron/main.ts`
- 单实例锁（保证同一 user-data 唯一写者；MCP stdio 模式故意不抢锁）
- `registerIpc()`：所有 `nomi:*` 通道集中注册在这里，是「主进程能干什么」的**唯一清单**
- 注入 CSP（dev 放宽给 HMR，prod 收紧）；COOP/COEP 跨源隔离**在 Windows frame:false 下主动跳过**（否则标题栏拖不动）
- 能力核（`capabilityCore`）、代理探测延迟到窗口创建后异步启动，不挡首帧

### 3.2 桥接层：`electron/preload.ts` → `window.nomiDesktop`
preload 用 `contextBridge.exposeInMainWorld("nomiDesktop", {...})` 把能力暴露给渲染层。渲染层**永远不直接碰 Node / Electron**，只通过 `window.nomiDesktop`。

`src/desktop/bridge.ts` 是对 `window.nomiDesktop` 的类型化封装，业务代码 `import { nomiDesktop } from "../desktop/bridge"` 来调主进程能力。通道分组示例：
- `projects.*` 项目读写、`assets.*` 素材、`tasks.run/result` 跑模型任务（含付费令牌 `grantSpend`）
- `modelCatalog.*` 模型目录、`onboarding.*` 接入向导
- `capability.*` 能力核 / 接入 AI 编程助手（Claude Code / Codex 当 MCP）
- `browser.*` 应用内浏览器（捕捞素材）、`exports.*` 导出、`conversations.*` / `memory.*` / `promptLibrary.*` 上下文记忆

> 想加新主进程能力？**三处要改**：`electron/main.ts`（注册 IPC handler）→ `electron/preload.ts`（暴露到 `nomiDesktop`）→ `src/desktop/bridge.ts`（加 TS 封装）。缺一不可。为什么这很痛、怎么根治，见下方 §3.5。

### 3.3 渲染层入口
- `src/main.tsx` → `src/NomiRouterApp.tsx`：HashRouter，路由决定进「项目库 / studio / settings / stats」等
- 状态管理 **Zustand**（如 `generationCanvasStore`），不引 Redux

### 3.4 单一数据来源：前端状态 ≠ 持久真相

两层数据，**别混**：

| 层 | 存哪 | 谁是唯一真相 | 例子 |
|---|---|---|---|
| 前端交互状态 | React/Zustand（内存） | ❌ 临时 | 画布拖拽中、选中态、未保存表单 |
| 持久真相 | 后端落盘（`projects/repository.ts`、`catalog/catalogStore.ts`、`workspace/workspaceRepository.ts`） | ✅ 唯一 | 项目 JSON、模型目录、资产本地化 URL |

- 渲染层改完 → 调 `nomiDesktop.xxx.write` → 后端原子的 `writeJsonFileAtomic` 落盘 → 必要时回读刷新 UI。
- 前端 Zustand **不是真相**，刷新/重启以落盘为准。改数据相关 bug 先问「这值在内存还是落盘」。

### 3.5 为什么「改一处会动多处」＋解耦计划

前端好改、后端庞大，根因不是文件长（最大 760 行 < 800 门岗），而是**两处架构性耦合**让改动跨层扩散：

**脆弱点 1 — IPC channel 是裸字符串，四层散落**
同一 channel 名 `"nomi:projects:read"` 散在 `main.ts`（注册）→ `preload.ts`（暴露）→ `bridge.ts`（封装）→ 前端组件（调用），靠人肉对齐字符串，**编译器不查、拼错不报错**。改名/改 sync→async/加参要手工翻四处。

**脆弱点 2 — `runtime.ts` 符号百货层 + 反向依赖**
`runtime.ts` 从 20+ 子模块 `re-export`；36 个文件 `import {…, type TaskRequest} from "../runtime"`；且 `catalog/` 6 个文件反向依赖它（目录域→运行时枢纽，方向乱）。改 `TaskResult` 字段要同时翻 tasks(4)+catalog(6)+providerAdapter+capabilityCore(5)。

**解耦计划（已写 `docs/plans/2026-08-10-decouple-ipc-runtime.md`，纯重构、不动业务）：**
- **A. IPC 常量化**：抽 `electron/shared/ipcChannels.ts` 常量表，四层统一引用 → 加 channel 编译器全链报错。最安全、收益最直观。
- **B. 拆 runtime 百货层**：消费方直接 import 真实归属模块，`catalog/*` 断开对 runtime 反向依赖，runtime 只留运行时上下文。

> 不要为了"文件少"去合并 `catalog/` 供应商适配——那是声明驱动多供应商的诚实代价，合并违反 P1 单职责，反而更不好改。

## 5. 工程纪律（动代码前必读 `AGENTS.md` 全文）

项目有极其严格的工程纪律，违反会被 CI 红。核心五条 + 关键规则：

**P1 加新必删旧** — 引入新实现同 commit 删旧实现，无并行版/无 fallback/无逃生口。CSS 同理：新样式只写组件 className，迁 Tailwind 即删旧 CSS；全局 CSS 只可减不可增。

**P2 修根因不修症状** — bug 先分「症状/根因/入口集」，修在根因层让整类不再复发。自检：「修完后还能从别的入口出现吗？」答不出"不能"=没到根因。

**P3 全绿 ≠ 完成** — CI 五门只证代码健康。用户可见改动报完成前：① 和获批样张逐项并排对账；② 真体感走查（Playwright 截图人眼判断）。

**P4 通用第一** — 能力/组件/交互按「模型身份 / 通用场景」设计，与具体供应商解耦。不为不同模型写两套 UI（那是并行版，违反 P1）。

**P5 想清楚再动手** — UI 改动先读设计系统 `docs/design/nomi-design-system.md` 再画；架构改动先查 Context7 官方文档 + 读顶尖开源 + 6 角色评审；多文件改动先写 `docs/plan` 文档。

**关键规则（R#）速记**：
- **R1/R10** 加新删旧；全局 CSS 只减不增
- **R3** 涉及取舍先给对比表（方案/用户看到/代价）
- **R4** 多文件/多步改动先写 `docs/plan`
- **R5** 碰第三方库必先 Context7；接任何模型前必抓真实官方 API 文档逐项对账，**禁凭记忆编**
- **R8** 用户可见改动先出 mockup + 用户拍板；实现后必须和样张对账
- **R9/R12** 单文件 ≤800 行；巨壳白名单只降不升（`check:filesize`）
- **R11** 验证通过即自己 commit + push；五门全过才能 commit
- **R13** 体验走查：Playwright 走真实用户旅程，截图人眼判断
- **R15** 所有用户可见文字走 i18n；当前仅 zh-CN / en

**决策自治（AGENTS.md P0）**：默认自主推进到底、不留遗留；评测/测试/验证类额度花费默认授权（真生成/真模型/VLM/E2E 直接花，事后报花多少）；只在「产品方向/不可逆取舍/架构岔路/需要用户独有资源/需求自相矛盾」时才问用户。

## 6. 设计系统与 Token（UI 改动必读）

- 设计系统真相源：`docs/design/nomi-design-system.md` + `src/design/`（token-only）
- **光/暗双模式**：默认按本地时间「天黑自动暗」；手动切一次后记住；token 翻转
- **密度优先**：界面信息密度高
- **Token 门岗（`check:tokens`）极其严苛**：禁止任意 px 字号/圆角、禁 hex 色、禁默认色板。所有视觉值必须 derive 自 token。新增一个硬编码 px/hex 即红。

---

## 7. 模型接入（最常见的改动场景）

用户接入新供应商/模型有两条路：
1. **UI 向导**（用户侧）：顶部工具栏「模型接入」→ 添加供应商（DeepSeek / 即梦 / 可灵 / Runway 等）。对应 `electron/onboarding/*` + `src/...onboarding`
2. **模型目录（catalog）**（开发者侧）：`electron/catalog/` 管理 vendor / model / mapping；支持 ComfyUI 工作流导入（`comfyui*`）、自定义调用（customCall 契约/AI 指令/试跑）

> **R5 铁律**：接入/改任何模型前，必先抓到该模型真实官方 API 文档，逐项对账端点/鉴权/变体/模式/参数，**禁凭记忆瞎编**。

## 8. 测试与质量门禁

- **单元测试**：`pnpm run test`（Vitest），主进程/渲染层都有 `*.test.ts(x)`
- **E2E 冒烟**：`pnpm run test:e2e`（Playwright，零额度，CI-ready）
- **体验走查（R13）**：`scripts/*.walkthrough.mjs` 是大量 Playwright 走查脚本，覆盖各功能旅程；截图需人眼判断
- **评测（evals/）**：`scripts/eval-*.mjs` 是评测/打分/对比工具，真跑模型（额度默认授权）

改完代码的最小验证闭环：`typecheck` → `lint:ci` → `test` → （用户可见改动）走查截图。

## 9. 能力核 / CLI / MCP（高级）

- 能力核（`electron/capabilityCore/`）让 Nomi 既能 GUI 用，也能被外部程序（Claude Code / Codex）当 MCP server 调
- **MCP stdio 模式**：`NOMI_MCP_STDIO=1` 把 Nomi 二进制拉起成 MCP server，只跑进程内 stdio JSON-RPC，不开窗、不抢单实例锁
- **「接入 AI 编程助手」卡**：一键把 Nomi 写进 `~/.claude.json` 的 `mcpServers.nomi`，详见 `docs/guide/capability-core-cli-mcp.md`

## 10. 常见坑与提示

- **onnxruntime-web WASM 多线程 warning**：`@imgly/background-removal`（背景擦除）想用 12 线程，但 Electron 在 Windows frame:false 下主动关了 COOP/COEP 跨源隔离（否则标题栏拖不动），于是 fallback 单线程。仅背景擦除略慢，**功能正常、非 bug**，一般不用修。
- **渲染层热更新不重启 Electron main**：改了 `electron/main.ts` 或 `preload.ts` 要**完全重启 `pnpm dev`** 才生效（main 进程不随 Vite HMR 重编译）。
- **dev 多实例**：`dev-electron.mjs` 按 renderer 端口隔离 user-data profile（`NOMI_ELECTRON_USER_DATA_DIR`），避免复用旧 Vite code cache。
- **首屏加载失败**：看主进程控制台 `[nomi:desktop] renderer load attempt N/20 failed`；Vite 没起来就等它起（脚本会重试 20 次 / 500ms）。
- **Windows 标题栏**：`frame:false` 自绘（`WindowControls`），仅 Windows；mac/Linux 保留原生 chrome。

## 11. 上手建议路径

1. 先跑通 `pnpm dev`，在界面里走一遍「建项目 → 接入模型 → 画布生成 → 导出」，建立用户视角（对应 01-用户指南）。
2. 读 `AGENTS.md`（纪律总纲，每轮都会自动注入三闸）。
3. 读 `docs/engineering-rules.md`（R1–R16 详解）+ `docs/coding-standards.md`（编码规范）。
4. 想改哪块，先 `list_dir` / `search` 定位到上面第 4 节的对应目录，读真实代码再动手。
