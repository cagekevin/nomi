# Skill 系统与 AI 提示词总览

> 探索范围：`electron/skills/*`、`electron/ai/agentChatV2.ts`、`src/config/prompts/*`、`src/workbench/generationCanvas/*`、`docs/skill-pack-format.md`、仓库根 `skills/`（30 个技能）。
> 目的：给开发者一份**总结性**地图——skill 散在哪、生命周期是什么、所有 AI 提示词落在哪、它们如何拼成每一次对话。
> 日期：2026-08-10
> 配套规范：`docs/skill-pack-format.md`（Skill Pack v2 人读格式）、`docs/plan/2026-06-19-skill-playbook-system.md`（playbook 设计依据）

## 〇、一句话心智模型

- **Skill = 纯文本方法论**，不是代码。`skills/<name>/` 下只有 `SKILL.md`（人话方法论，作为 system prompt 注入）+ `skill.json`（机读 manifest：工具白名单、所需 provider、阶段骨架）。
- **提示词不是单一文件**，而是分三层拼出来的：`NOMI_AGENT_IDENTITY`（共享身份） + 当前面专长（如画布工具集） + 当前 skill 方法论。各面只叠自己的专长层，身份只在一处定义。
- **skill 不自动执行任何外部动作**。运行时只把 SKILL.md 当知识注入；里面提到的 CLI/HTTP 不会自动跑，除非当前对话/界面明确提供了对应工具。

| 文件 | 职责 | 关键函数 |
|---|---|---|

## 二、Skill 数据结构（manifest 字段）

来源：`electron/skills/skillManifestSchema.ts:79-107`

| 字段 | 类型 | 说明 |
|---|---|---|
| `name` | string | 全局唯一稳定 key，如 `workbench.storyboard.planner` |
| `version` | string | SemVer 串（schema 强制必填） |
| `description` | string | 一句话 UI 摘要 |
| `tools` | string[] | 工具白名单（只这些工具对 LLM 可见） |
| `requiredProviders` | `("text"\|"image"\|"video")[]` | 端到端需要的 provider 模态 |
| `permissions` | `("read-only"\|"create"\|"delete"\|"export")[]` | 能力门 |
| `inputs?` / `examples?` | 可选 | 声明输入字段 / 示例 prompt |
| `stages?` | `SkillStage[]` | 多段 playbook 骨架；**缺省 = 单段 legacy 包**，向后兼容 |
| `author?` / `label?` | 可选 | 卡片展示用 |

**`SkillStage`**（playbook 段）：`id` / `goal` / `tools[]` / `dependsOn?` / `pause?`（缺省 true）/ `modelPrefs?[]`。

**阶段模型偏好硬约束**（`skillStageModelPrefSchema:48-55`，`.strict()`）：只声明能力身份 `kind` + 可选 `family`（如 `seedance`），**绝不绑 vendor 专属 `archetypeId`，也不写死 `params`**——这是「通用第一 + 分享出去不绑死」的硬约束。

## 三、Skill 生命周期（完整链路）

```
定义(SKILL.md+skill.json)
   │
   ▼  发布/内置
[内置] 仓库根 skills/ → 打包进 resources/skills（随安装包，只读）
[用户] 自己建 / 从他人导入（skillPackage 异步文件交换）
   │
   ▼  加载（每次对话热路径，readSkillRecords）
扫所有 skills 根 → 解析 frontmatter + skill.json
   ├─ origin 判定：目录在 userData/skills ⇒ 'user'（可删/可导出）
   │              否则 ⇒ 'builtin'（只读、禁删）
   └─ 多根去重：「先出现的根」胜（内置优先）
   │
   ▼  请求匹配（findSkillRecord）
精确 name → 前缀匹配 → 归一化模糊匹配（处理大小写/分隔符差异）
   │
   ▼  注入（buildSkillSystemPrompt → 拼进 system prompt 第三段）
   │
   ▼  执行
单段：直接当知识注入 system prompt
多段(playbook)：playbookOrchestrator 按 dependsOn 拓扑排序逐段跑，
                每段按 tools 白名单收紧 gate，pause 段完成后等用户审阅
   │
   ▼  下架/移除
builtin：随安装包更新/移除（代码不删，只读目录碰不到）
user：deleteUserSkill（必须严格落在 userRoot 内，防 .. 穿越）
```

### 存放位置与多根扫描
`electron/runtimePaths.ts:50-60` `getSkillsRoots()` 依次尝试：
1. `NOMI_SKILLS_DIR`（env 覆盖，测试/隔离用）
2. `process.cwd()/skills`
3. `app.getAppPath()/skills`（开发态内置）
4. `__dirname/../skills`
5. `process.resourcesPath/skills`（**打包后内置随附位置**）
6. `getUserSkillsRoot()` = `getSettingsRoot()/skills`（用户可写）

### 版本与锁
- manifest 自带 `version`（必填）。
- ⚠️ **`skills-lock.json` 在代码里没有引用**——仅在 `AGENTS.md`/`CLAUDE.md`/`docs/11-工程纪律详解` 提及，**未实现**。版本管理目前只靠 `manifest.version`，无锁版本文件。

### 导入/导出/删除安全（`skillPackage.ts`）
- 包格式 `nomi-skill-v1`，纯 JSON（skill 是纯文本，无需 zip）。
- 导入：`validateSkillPackage` 校验版本 + 文件名安全（拒 `..`/可执行扩展）+ 必含 SKILL.md + skill.json 合法；冲突目录名自动加 `-2/-3`（**不覆盖内置**）。
- 删除：`deleteUserSkill` 解析后必须严格落在 `userRoot` 内（防穿越），只删 `userData/skills`。

## 四、内置 Skill 清单（仓库根 `skills/`，30 个）

按目录前缀分族（来源：`skillStore.ts:148` 仅 `director-`/`writer-` 前缀对 MCP 脊柱外暴露）：

| 族 | 成员 | 性质 |
|---|---|---|
| `director-`（导演方法论，外暴露） | action / art-design / cinematography / consistency / guzhuang / keyframe-review / performance / shot-translation / sound / staging / style-otomo-wright / transitions | 电影方法论库，供内外 agent 按需调用 |
| `writer-`（编剧方法论，外暴露） | adaptation / behavior-psychology / dialogue / improv / incubation / novel-digester / review / screenwriter / songfangjin / structure / style-schrader | 同上 |

### 5.6 创作区 skillKey 映射规则（2026-08-10 补）
创作区 `runWorkbenchAgent` 的 `skillKey` 决定注入哪个 skill 的方法论层（`CreationAiPanel.tsx:320`）：

| 场景 | `skillKey` 取值 | 对应 skill |
|---|---|---|
| 用户手动锁定 playbook（如「品牌宣传片」） | `activeSkill.key`（如 `brand-promo`） | `skills/brand-promo` 等 |

## 六、提示词与 skill 的关系（设计意图）

- **提示词 = 三层拼装**，不是「写在某一个文件」：
  `system = NOMI_AGENT_IDENTITY`（共享） + 面专长静态段（`generationCanvasAgent.ts` 画布工具集 / `creationAiModes.ts` 创作区 7 模式专长，见 §5.2） + `skillSystemPrompt`（skill 方法论）。
- **skill 即「可分享的提示词包」**：`SKILL.md` 就是一段会被注入 system 的方法论提示词；`skill.json` 描述它的工具/provider 边界。分享 skill = 分享提示词（纯文本）。
- **「提示词即 skill」模式已落地**：`workbench-*` 系列就是幕后提示词包；`brand-promo` 是用户可见的 playbook 提示词包。
- **character-fixation 提示词是代码内 prompt**（非 skill）：`fixationPromptTemplates.ts` 里硬编码，因它要按剧本反推 expressions/outfits 等动态拼装，比静态 skill 更需要运行时参数化——符合「参数化强的走代码，方法论强的走 skill」。
