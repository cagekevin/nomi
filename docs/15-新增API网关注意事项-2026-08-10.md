# 15 · 新增 API 网关注意事项（接入实战 check-list）

> 开发者-facing 实战文档（developer-facing）。目标：把「以后 Nomi 再加一个 API 网关 / 私有中转」**最容易踩的坑**讲清楚，给一份能照做的 check-list。
> 定位：**04 文档（`04-第三方API接入机制探索-2026-08-10.md`）讲"接入机制怎么跑"（机制篇）**；本篇讲"加网关时**必须核对哪些点、为什么**"（实战篇），踩坑全部来自 2026-08-10 真实事故 + lovart 网关源码实证。
>
> 一句话：**Nomi 的三层参考图键设计（档案 inputKey → archetypeInput → params → 渠道模板）是静默丢参考图的温床，新增网关最大的坑不在"调通请求"，而在"参考图键名对齐 + 档案选对 + 能力边界如实声明"。**

---

## 0. 心智模型：加一个网关 = 加 3 样东西，但真正的坑在「对齐」

加一个 API 网关，代码上要加三样（04 文档已讲）：
1. **vendor**（`lovartVendor.ts` 式：base URL + 鉴权 + 契约注释）
2. **curated model + mapping**（`lovartImages.ts` / `lovartVideos.ts` 式：每个模型的能力档案 + create body 模板）
3. **seed 注册**（`seedBuiltins.ts`：把 model/mapping 塞进 catalog，`reconcileMappings` 自动对账自愈）

**但加网关最贵的不是这三样本身，而是「对齐」**——你的网关字段名，要和 Nomi 档案 slot 的 inputKey、以及第三闸的判定**三方一致**。任一处不一致，参考图就**静默发不出去**（生成成功、扣费成功、和参考图毫无关系），或者被第三闸如实拦住（报"发不出参考图"）。

---

## 1. 核心陷阱 ①：参考图键名必须「档案 inputKey == 你的网关字段」（最易踩）

### 为什么
Nomi 的参考图发送链路：
```
档案 slot.inputKey（如 gpt-image-2 图生图 = input_urls）
   → buildArchetypeInputParams 把参考图写进 extras.archetypeInput.<inputKey>
   → taskTemplateParams 铺成 params.<inputKey>
   → 你的 mapping body 用 {{request.params.<key>}} 读它
```
**渲染层只往「档案声明的 inputKey」这个键里放参考图**。如果你的 body 读的是**别的键**，运行时 `params.<那个键>` 就是 `undefined` → 参考图进不了请求体。

### 真实事故（2026-08-10）
`lovartImages.ts` 的 GPT Image 2 三档改图 body 读 `{{request.params.image_urls}}`，但 gpt-image-2 档案图生图槽 inputKey 是 **`input_urls`**（kie 契约）。渲染层把图写进 `input_urls`，body 读 `image_urls` → 参考图永远发不出。同构的 `apimartImages.ts` 早就写对了（`image_urls: "{{request.params.input_urls}}"`），lovart 漏了。

### 怎么避免
**对照源码，别猜**。加网关时逐一核对：
1. 读对应模型档案（`src/config/modelArchetypes/*.ts`）里**图生图/图生视频模式每个参考槽的 inputKey**（显式 `inputKey:` 优先；缺省看 `referenceReachability.ts` 的 `DEFAULT_SLOT_INPUT_KEY`）。
2. 你的 body 引用的 `{{request.params.<key>}}` **必须逐字等于** 这些 inputKey。
3. **跑机器校验**：`electron/catalog/referenceSlotConsistency.test.ts`（仿 `paramConsistency.test.ts`）遍历所有内置 mapping，自动报「渠道 body 发不出档案声明的参考槽」。**新增网关后这条必须绿。**

---

## 2. 核心陷阱 ②：档案选对——协议兼容不等于槽结构兼容

### 为什么
**同属 APIMart 协议兼容，不等于参考图槽结构一致。** 网关是 APIMart 协议（扁平 `image_urls` 一族），不代表它该用 kie 风格的多槽分离档案。

| 档案 | 图生视频参考槽 inputKey | 适合 |
|---|---|---|
| `seedance-2`（通用，kie 契约） | `first_frame_url` / `reference_image_urls` 等分离键 | kie 官方 |
| `seedance-2-apimart`（apimart 契约） | `image_urls` / `video_urls` / `audio_urls` / `image_with_roles` | apimart / lovart 网关 |

### 真实事故（2026-08-10）
`lovartVideos.ts` 的 Seedance 用了通用 `seedance-2` 档案，但 lovart 网关只读扁平 `image_urls` → 首帧/全能参考**全部发不出**（参考槽一致性测试抓出 12 处）。修法：改用 `seedance-2-apimart` 档案（槽 inputKey 与网关契约一致）。

### 怎么避免
**看网关源码，确认它到底读哪些字段**，再选档案：
- 网关读 `image_urls` 一族扁平键 → 选 apimart 风格档案
- 网关读 `first_frame_url`/`reference_image_urls` 一族分离键 → 选 kie 风格档案
- 都不匹配 → **建独立档案**（能力结构差异 → 独立档案，见 `seedanceApimart.ts` 头注释）

---

## 3. 核心陷阱 ③：能力边界如实声明——网关不支持的别硬发

### 为什么
网关对「全能参考 / 首尾帧 / 参考视频/音频」的支持，**只有网关源码说了算**，不能从协议推断。

### 真实事实（lovart 网关 `main.py` 源码实证，2026-08-10）
`_do_submit` 提取参考素材**只读**这些键：
```
image_urls / images / attachments / reference_images
videos / reference_videos / audios / reference_audios / files
```
**不读** `image_with_roles` / `video_urls` / `audio_urls` / `first_frame_url` / `last_frame_url`。
且这些 URL 统一提取进 `attachments` 透传、由 Lovart 端自识别类型——网关对视频参考**只可靠支持图片（image_urls）**。

### 怎么避免
- 接网关前，**读网关 `main.py`（或等价实现）的 `_do_submit` / 请求体解析**，列出它真实读取的字段清单。
- 网关不支持的参考能力（如参考视频/音频），**要么 UI 不暴露（建独立档案只给支持的模式），要么接受第三闸诚实拦截**，别让 body 发了网关不读的字段还假装"支持"。

---

## 4. 参数一致性也别漏（`paramConsistency` 看门狗）

换档案 / 加网关时，**canonical 参数**（比例/清晰度/时长/种子）也要对齐。`electron/catalog/paramConsistency.test.ts` 遍历所有内置 (模型×模式)，检查「档案每个参数都被 codec 覆盖或显式 drop」。新增网关后这条也必须绿。

真实案例（2026-08-10）：lovart 视频换到 `seedance-2-apimart` 档案后，该档案参数里有 `seed`，但 lovart body 没引用 → `paramConsistency` 当场报「seed 未覆盖」。修法：body 补 `seed` 引用（对齐 apimart）。

---

## 5. 加网关的完整 check-list（照做）

新增一个 API 网关（vendor + model/mapping + seed）后，**逐条核对**：

- [ ] **参考槽键对齐**：body 引用的 `{{request.params.X}}` 逐字等于档案 slot 的 inputKey（§1）
- [ ] **档案选对**：根据网关源码实际读取的字段，选 apimart/kie 风格档案或建独立档案（§2）
- [ ] **能力边界**：网关不支持的参考（视频/音频/首尾帧）要么 UI 隐藏、要么诚实拦截，不硬发（§3）
- [ ] **参数覆盖**：body 或 paramMap 覆盖档案所有 canonical 参数（含 seed 等），不依赖静默丢弃（§4）
- [ ] **paramMap 对齐新档案**：换档案后 paramMap 的 `from` 键要匹配新档案的 canonical 键（如比例键是 `size` 还是 `aspect_ratio`）
- [ ] **独立成家**：本地/私有网关**不要复用 APIMart 卡**（apimart 是付费核心通道），建独立 vendor（`04` 文档 §0 已强调）
- [ ] **跑看门狗**：
  - `npx vitest run electron/catalog/referenceSlotConsistency.test.ts`（参考槽一致）
  - `npx vitest run electron/catalog/paramConsistency.test.ts`（参数一致）
  - `npx vitest run electron/catalog/seedBuiltins.test.ts`（seed 注册）
  - `npx vitest run electron/catalog`（全 catalog 无回归）
- [ ] **类型检查**：`npx tsc -p electron/tsconfig.json --noEmit` + `npx tsc -p tsconfig.app.json --noEmit`

## 6. 10 分钟极简 checklist（照着打勾）

> 下次加网关时，**先拿网关契约，再动手**。这条过不了，后面再顺也会翻车。

**第 0 步 · 拿契约（唯一可能"不畅通"的环节）**
- [ ] 拿到网关真实请求契约：源码（`main.py` 的 `_do_submit`）/ 官方文档 / swagger
- [ ] 从中列出网关**真实读取的参考字段清单**（如 `image_urls` / `videos` / `reference_videos` …）
- [ ] 没拿到契约 → 停下问供应商，别猜键名（这次能收敛全靠你给了 `main.py`）

**第 1 步 · 选档案（§2）**
- [ ] 网关读 `image_urls` 一族扁平键 → 选 apimart 风格档案
- [ ] 网关读 `first_frame_url`/`reference_image_urls` 一族分离键 → 选 kie 风格档案
- [ ] 都不匹配 → 建独立档案（能力结构差异 → 独立档案）

**第 2 步 · 写 body（§1 / §3）**
- [ ] body 里 `{{request.params.X}}` 逐字等于档案 slot 的 inputKey
- [ ] 网关不读的字段（如参考视频/音频/首尾帧）**不写进 body**，或 UI 不暴露该模式
- [ ] body / paramMap 覆盖档案所有 canonical 参数（含 `seed`），不依赖静默丢弃

**第 3 步 · 注册 + 跑门岗**
- [ ] seed 注册进 `seedBuiltins.ts`
- [ ] `npx vitest run electron/catalog/referenceSlotConsistency.test.ts` ← 全绿（抓参考图静默丢失）
- [ ] `npx vitest run electron/catalog/paramConsistency.test.ts` ← 全绿
- [ ] `npx vitest run electron/catalog` ← 全 catalog 无回归
- [ ] 手动走查一次带参考图的真实请求（确认图真进了 wire，不只测试绿）

**判断**：第 0 步契约到位 + 第 3 步门岗全绿 = 基本复现本次的顺。第 0 步缺失 = 唯一可能卡住的点。
