## 〇、这块为什么特殊：素材盒是独立透明窗口，DOM 点击测不到「点穿」

这是改/测这块最容易踩、最容易漏测的地方，务必先理解机制再动手：

- 「素材盒」浮层不是普通 DOM 弹层，而是一个**独立的透明 `BrowserWindow`**（`electron/browser/overlay/browserViewOverlay.ts` 的 `ensureBrowserAssetOverlay`：`transparent:true`、`frame:false`、`setIgnoreMouseEvents(true, {forward:true})`）。
- 它的「可点性」靠 OS 级机制，主进程每 **80ms** 轮询系统光标位置（`startBrowserAssetOverlayHoverTracking` 的 `setInterval(..., 80)`），对账「上报的可点热区 `popoverRect`」，命中才让窗口接收鼠标；吸附态（dock）还叠一层 `setShape` 裁剪（仅 win32/linux 生效，macOS 不支持 `setShape`，靠 `hoverInteractive` 全窗命中兜底）。
- 可点性由四个交互态共同决定（`applyBrowserAssetOverlayMouseEvents`）：`shapeInteractive`（吸附 shape）∨ `pointerInteractive` ∨ `hoverInteractive` ∨ `dragInteractive`，任一为真才 `setIgnoreMouseEvents(false)`。
- **核心不变量**：上报的可点热区必须覆盖「可交互内容实际在哪」。热区外的控件，真机点它会**穿透到背后的网页**。
- **Playwright / `page.click()` 给渲染进程派的是合成事件，绕过整个窗口机制**——DOM 里的按钮永远显示「能点」，`setIgnoreMouseEvents` 造成的穿透死区它**完全看不见**。所以：
  - ❌ 不要只用 Playwright DOM 点击判断「这个控件能不能点」（永远 true，测了等于没测）。
  - ✅ 用「几何对账」：把上报热区 `window.__nomiOverlayHitRect`（屏幕坐标，代码已挂，见 `BrowserAssetOverlayApp.tsx` 的 `hostRect` 内省）与每个可交互元素的 `getBoundingClientRect()` + overlay 窗口屏幕原点比对。**任何中心落在热区外的可交互元素 = 真机必穿透 = bug**。

## 一、环境与启动（零额度、隔离）

```bash
pnpm install            # 若 node_modules 软链缺依赖，rm -rf node_modules && pnpm install
pnpm build              # 全新构建，防 stale-chunk 伪 bug
```

跑法二选一：

- **一次性走查脚本**（推荐，含几何不变量断言）：
  ```bash
  node tests/ux/browser-overlay-interaction.walk.mjs   # 素材盒浮层交互 + 几何不变量（穿透守卫）
  node tests/ux/reference-capture.walk.mjs             # 网页捕捞→落库→显示名 + 防盗链 全链路
  ```
  两个脚本用隔离 `--user-data-dir` + `NOMI_E2E` 环境变量，零额度。
  - ⚠️ 收尾若 `app.close()` 挂死会留僵尸 Electron；`finally` 已做「close 竞速 8s → SIGKILL」。`pnpm run kill:zombies` 清场。
  - 探索期别每轮 launch→close，用常驻驱动 `tests/ux/ui-driver.mjs`（见 `16-UI自主走查方法-2026-08-10.md`）。
- **给人真点的沙盒**（真机复现真站 bug 用）：
  ```bash
  mkdir -p /tmp/nomi-t/projects
  NOMI_PROJECTS_DIR=/tmp/nomi-t/projects NOMI_E2E_ALLOW_MULTI_INSTANCE=1 \
    npx electron . --user-data-dir=/tmp/nomi-t/udata
  ```

启动后路径：项目库 → 新建/打开项目 → 生成区（顶栏「生成」）。
- 打开浏览器：顶栏「浏览器」按钮（或渲染层派 `window.dispatchEvent(new CustomEvent('nomi-open-browser'))`）。
- 打开素材盒：浏览器工具条右上「素材盒」按钮（或派 `nomi-browser-asset-popover-open` `{opened:true}`）。

## 二、几何不变量测试（穿透类 bug 的唯一程序化验证）

对**素材盒每一个可交互元素**（工具条按钮、tab、搜索框、格子、菜单项、以及每个弹框内的控件），在浮层打开态（含吸附态、含各弹框打开态）下：

- 读上报热区：overlay 页 `window.__nomiOverlayHitRect`（overlay 局部坐标，需加 overlay 窗口 `getContentBounds()` 原点转屏幕坐标）。
- 读元素屏幕坐标：overlay 窗口屏幕原点 + 元素 `getBoundingClientRect()`。
- **断言**：元素中心落在热区内。任何落在热区外的可交互元素，写进报告（=真机点穿）。
- 特别覆盖：吸附态（dock right/left）+ 各弹框（提示词提取设置 / 提示词详情 / 右键菜单 / ⋮菜单）打开时，弹框内控件是否都在热区内。

现成守卫 `tests/ux/browser-overlay-interaction.walk.mjs` 已实现并持续扩展，关键断言节点：

| 节点 | 断言 | 为什么 |
|---|---|---|
| ① 默认态 | 热区 ≈ 卡片矩形（非整窗） | 卡片外应点穿到网页，这是设计意图 |
| ③ 提示词提取设置打开 | 热区扩到整窗（`hitExpandedToFull`）+ 设置框内控件中心在热区（`modalBtnInHit`） | 曾用 `fixed inset-0` 铺满整窗但热区只覆盖卡片 → 设置框被点穿（已修：溢出整窗模态在场时热区扩到整窗）。`modalOutsideCard` 证明面板确实伸出卡片外，修复有意义 |
| ④ 关闭设置 | 热区缩回卡片 | 修复不能常驻全窗，否则卡片外永远挡网页 |
| ⑦ 吸附右侧 | 全部可见控件中心在热区（`dockControlsInHit`） | dock 态 shape/命中区偏移后易漏控 |
| ⑩ 重开 | 素材盒完整可见 + 全部控件在热区 | 收起/重开不能留幽灵 overlay 或死区 |

## 四、已知待根治 bug（复现 + 根因 + 修）

**★ Dribbble 图捕捞/拖拽「下载失败」（最高优先，未根治）**：
- 复现：浏览器开 `https://dribbble.com/` → 拖/捕捞任意 shot 缩略图进素材盒 → 卡片「下载失败」。真实失败例：`27549099-Satara-...`、`27548809-WPStar-...`。
- 已知：`importMedia`（会话下载）对 picsum.photos 等普通 https 图**成功**，所以下载路径本身没坏；是 Dribbble CDN 特定（疑似防盗链头不足 / 内容类型 / srcset 懒加载占位或 blob）。
- 已加：会话下载失败 → 直连拉取兜底 + 错误按 超时/403防盗链/blob 分诊到卡片副标题。但用户最新截图仍纯「下载失败」——分诊没命中或走了别的路，**需抓真实 Electron 主进程错误**（在 `electron/browser/media/browserViewMedia.ts` 的 `downloadBrowserMediaFromPageView` 打点，看 `will-download` 是否触发、`downloadItemMatchesUrl` 是否因重定向不匹配、下载项 state/mimeType）。根因定位后修死。相关文件：
  - `electron/browser/media/browserViewMedia.ts`（`importBrowserMedia` / `downloadBrowserMediaFromPageView`）
  - `src/ui/browser/popover/browserAssetPopoverUtils.ts::readBrowserImageDragPayload`（拖拽提取的 URL）
  - `src/ui/browser/overlay/BrowserAssetOverlayApp.tsx::importBrowserAssetToLibrary`（选 importMedia vs importRemoteUrl）
  - `src/ui/browser/popover/useBrowserAssetCaptureImport.ts`（错误分诊文案）

**其它需复核不回归的近期修复**（门岗/走查守卫）：
- 素材盒工具条「素材盒」按钮点开弹层（曾只翻 React 状态不调 native open → 打不开）
- 「提示词提取设置」弹框吸附态可点（穿透修复，几何不变量守卫）
- favicon 裂图回退
- 捕捞素材显示网页标题而非哈希名（`assetSurfaceInvariants.test.ts` + 三处平行映射）
- **唯一门不变量**（`src/ui/browser/assetSurfaceInvariants.test.ts`，进 `pnpm run test`）：素材盒只在浏览器域出现，全局素材盒浮窗（宿主A）文件/入口/事件全仓零引用
