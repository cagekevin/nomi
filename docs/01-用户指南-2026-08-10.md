# 用户指南 · 构建后如何装好依赖

> 适用场景：你拿到了 Nomi 的源代码（或刚 `git clone` 下来），想从零把它 build 起来并跑通。本指南聚焦**装依赖**这一环，以及构建前最容易踩的坑。

---

## 一句话结论

Nomi 用 **pnpm** 管理依赖，不是 npm/yarn。装依赖只有一条命令：

```bash
pnpm install
```

前提是：**Node ≥ 20.19.0** 且 **pnpm ≥ 10.8.1**（版本锁在 `package.json` 的 `packageManager` 字段）。

---

## 1. 先备好环境

### Node.js

要求 `>=20.19.0`（见 `package.json` 的 `engines`）。

```bash
node -v   # 确认 ≥ 20.19.0
```

没装或不满足就先去装：[nodejs.org](https://nodejs.org)（LTS 即可，但要 ≥ 20.19）。

### pnpm

项目锁定 `pnpm@10.8.1`。推荐用 **corepack** 让 Node 自动选版本（不需要手动记版本号）：

```bash
corepack enable          # 首次启用，可能需要管理员/权限
corepack prepare pnpm@10.8.1 --activate
pnpm -v                  # 确认是 10.8.1
```

> 没 corepack 的老 Node？`npm i -g pnpm@10.8.1` 也行，但 corepack 更省心、和 `package.json` 锁的版本一致。

---

## 2. 装依赖（核心步骤）

在仓库根目录执行：

```bash
pnpm install
```

这一步会做两件事：

1. 安装 `package.json` 里所有依赖（含 Electron、Vite、ffmpeg/ffprobe 安装器等）。
2. 触发 `postinstall` 脚本（`scripts/install-git-hooks.cjs`），自动装好 git hooks。

### 为什么必须用 pnpm？

`package.json` 里有一张 `pnpm.onlyBuiltDependencies` 白名单，限定了「哪些包允许在 install 时跑原生构建脚本」：

- `electron`、`esbuild`
- `@ffmpeg-installer/*`（win/linux/mac 各架构）
- `@ffprobe-installer/*`（win/linux/mac 各架构）

这是 pnpm 的「只允许白名单包编译」安全机制。用 npm/yarn 装会**忽略这张白名单**，导致 ffmpeg/ffprobe 二进制装不上，后面导出 MP4 时会炸。所以别换包管理器。

> Windows 上 `@ffmpeg-installer/darwin-arm64` 和 `@ffprobe-installer/darwin-arm64` 在 `ignoredBuiltDependencies` 里被显式跳过（非 mac 用不到），属正常，无需担心。

## 3. 常见装依赖报错 & 处理

| 现象 | 原因 | 处理 |
|------|------|------|
| `ERR_PNPM_UNSUPPORTED_ENGINE` | Node 版本太低 | 升级 Node 到 ≥ 20.19.0 |
| `pnpm: command not found` | 没启用 pnpm | 跑 `corepack enable` |
| 装到一半卡在 `electron` 下载 | 网络拉不到 Electron 二进制 | 挂代理后重试；或设 `ELECTRON_MIRROR` 环境变量 |
| `ffmpeg`/`ffprobe` 相关报错 | 被 `onlyBuiltDependencies` 拦了 | 确认用的是 pnpm（不是 npm）；不要手动加 `--config.dedupe-peer-dependents` 之类覆盖 |
| `postinstall` git hooks 失败 | 仓库不在 git 内 / 权限 | 忽略即可，仅影响 git 提交钩子，不影响 build |
| 权限报错（`EACCES`） | 全局目录没写权限 | 别用 `sudo`；改用 corepack 或 nvm 管理 Node |

---

## 4. 装完验证

依赖装好后，可以快速验证环境健康：

```bash
pnpm run typecheck   # 类型检查，能跑通说明 TS 依赖齐了
```

或者直接进入构建：

```bash
pnpm build           # 编译前端 + Electron 主进程（build:renderer + build:electron）
pnpm dist            # 可选：打包成 DMG / EXE 安装包
```

开发模式（不打包，热更新）：

```bash
pnpm dev
```

---

## 5. 最低可用命令清单（抄这条就行）

```bash
corepack enable
pnpm install
pnpm dev          # 开发预览，自动开 Electron 窗口
# 或
pnpm build        # 仅构建
```
