# 16 · UI 自主走查方法（面向未来开发）

> 最后更新：2026-08-10 · 由 `archive/history-2026-workflow/2026-06-10-autonomous-ui-test-method.md` 重写
> 旧文是「2026 当时要不要接 Midscene」的调研定稿；现状已演进——本文去掉调研噪音，只留**现在改 UI / 跑走查该怎么做的实战方法**，每条都对照过真实代码（`tests/ux/ui-driver.mjs`、`tests/ux/*.walk.mjs`、`src/design/`）。

## 一、方法定位：AI 作 computer-use 智能体 + 现有常驻驱动

做「特别完整的用户测试」（点遍每个按钮、看遍每页、挖根因）**不需要外部工具**。那个自主点击的智能体就是 AI 本身，驱动层用项目已有的 `tests/ux/ui-driver.mjs`：

- 驱动基于 Playwright `_electron`，能挂上主进程 + IPC 桥（普通浏览器预览工具附不上 Electron）。
- `ui-driver.mjs` 启动后常驻不关：AI 用 `snap` 看真实可点元素 → 判断 → `click/fill/setfile/drag` → `shot` 截图人眼判断 → 再 `snap`。感知→决策→行动→再感知。
- 多窗口（v0.10.13+ 打开项目会新开 studio 窗口）已处理：`getWin()` 始终追「活窗口」，优先 hash 含 `projectId=` 的 studio 窗口，消除关窗竞态 / 串台。
- 多会话隔离：`UI_DIR` 按 worktree 派生唯一 IPC 目录；需要完全隔离实例时设 `NOMI_UI_USER_DATA` 起一份新 userData（否则抢默认单实例锁起不来）。

### 为什么不接 Midscene 等外部自主探索工具（结论保留，理由更新）

- `ui-driver.mjs` 已是 Electron 正确工具：DOM 感知、免费、零额度、主进程+IPC 全在。
- Midscene 要 vision-model 额度（属「需用户独有资源」决策），且对 Electron 仍是视觉/CDP 旁路，不比现有驱动更准。
- 仅在「将来要无人值守批量爬遍每个按钮」时再评估接 Midscene（需用户拍板额度）。

## 二、标准动作（每次完整用户走查照做）

1. **清场**：关掉已安装的 `Nomi.app`（`osascript -e 'quit app "Nomi"'`，否则抢 single-instance 锁）；杀残留 Electron / 驱动进程。`pnpm run kill:zombies` 可清僵尸 Electron。
2. **全新构建**：`pnpm build`。防 stale-chunk 伪 bug（改 renderer 要 `npx vite build`，改 electron 要 `npx tsc -p electron/tsconfig.json`）。
3. **起常驻驱动**：`node tests/ux/ui-driver.mjs`（后台跑，`Bash run_in_background:true`）。等 `/tmp/nomi-ui/ready`（实际路径见 `UI_DIR` 派生）出现后开始发命令。
4. **走真实旅程**（不是功能探索）：项目库 → 新建/打开项目 → 生成区（顶栏「生成」）→ 浏览器 → 素材盒。每步 `snap` 看可点元素 → 判断 → 操作 → `shot` + 人眼读图。
5. **交互态收尾**：逐个打开弹层/下拉/面板，看遮挡/溢出（吸附态、窗口边缘极端位置都看）。
6. **挖根因**：发现问题用 Explore agent 定位 `file:line`，分「症状 / 根因 / 地基（这类 bug 的入口集）」。
7. **落档**：走查报告（每项 PASS/FAIL + 截图路径 + 根因），问题分级 + 局部/地基拆分。
8. **收**：`ui.mjs quit`，别留后台窗口；迭代完 `pnpm run kill:zombies`。

### 驱动命令速查（`tests/ux/ui.mjs` 发 JSON 给 `ui-driver.mjs`）

| 动作 | 说明 |
|---|---|
| `snap` | 当前窗口所有可见可交互元素的 标签/文字/aria/中心坐标，AI 据此决定点哪，不盲猜 |
| `shot <name>` | 截当前活窗口图到 `tests/ux/shots/` |
| `click <target>` | 支持 `aria:xxx` / `css:sel` / `text:xxx` / `xy:120,80`；默认按可见文字模糊匹配 |
| `fill <sel> <val>` / `setfile <sel> <path>` | 填表 / 上传（`setfile` 绕过系统文件对话框，测上传不用真弹窗） |
| `drag x1,y1 x2,y2` | 真鼠标拖拽（trim/拖片/reorder/scrub 等手势，click 测不了） |
| `probe-latency <target>` | 测「点击→首视觉反馈」与「内容沉降」延迟 + 有无 skeleton/spinner/进度 |
| `fps-start` / `fps-stop` | 帧率 + longtask 测量 |
| `density` / `contrast <sel>` | 认知密度（可见可点元素数 + 文本量）/ 对比度比值（真实 RGBA 回读，支持 oklch/var） |

## 三、能覆盖 / 覆盖不到（诚实边界）

- ✅ 渲染层交互 + 感知判断（~90%）、上传（`setfile` 绕过系统对话框）、跨项目状态、几何实测、体验探针（延迟/帧率/密度/对比度）。
- ⚠️ **真实生成要额度**：vendor HTTP 在主进程发，渲染层抓不到。要验证真实生成链路用 `docs/archive/history-2026-workflow/2026-06-06-real-generation-e2e-loop.md` 的埋点方法。
- ⚠️ **原生 OS 对话框**：需 `electronApp.evaluate` stub `dialog.*` 才能驱动。
- ⚠️ **窗口穿透类 bug**（素材盒浮层点穿到网页）：DOM 合成点击测不到，必须走「几何对账」——见 `17-浏览器素材盒走查与不变量-2026-08-10.md`。

## 四、和五门 / 门岗的关系

- 走查是「人眼 + 驱动」的宽覆盖探索，发现的问题应**尽量落成永久断言**进 `tests/ux/*.walk.mjs` 或 `*.test.ts`（进 `pnpm run test` 的合并必经之路），避免只活在一次性走查里。
- 例：`src/ui/browser/assetSurfaceInvariants.test.ts` 把「素材盒只在浏览器语境出现」搬进了五门 test lane（外部 PR#41 曾捎带恢复全局素材盒浮窗，合并只跑 typecheck/test/build 没拦住，故加此门）。
- 报完成前必真机走查：全绿 ≠ 完成。截图必须自己亲眼读过（产出截图 ≠ 看过截图）。
- push 前五门全过：`pnpm run gates`（filesize → tokens → lint(max-warnings 棘轮) → typecheck → test → build）。

## 五、铁律（违反直接判不合格）

- 改任何 UI 前先看它真实样子（读完整外壳组件或先跑起来截真图），样张 = 真实布局 + 改动，不是脑补。
- 修 bug 挖根因：修在根因层，答得出「这类不再从别处复发」才算完。
- 加新必删旧：引入新实现同 commit 删旧，无并行版、无 fallback、无逃生口。
- 分支先 `git branch --show-current` 确认，别在被并行狂改的树上乱 commit。
